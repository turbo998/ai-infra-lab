## 1. 执行结论
1. 医院收入周期 AI 项目要想稳定落地，必须把临床捕获、证据锚定编码、确定性医保通道拆成独立控制平面。
2. 推荐采用三层分工模型，并把责任链与审计链前置到架构层。
3. **层 A**：EHR 内嵌 SMART on FHIR + 环境 CDI，负责实时捕获病历特异性缺口和医生问询闭环。
4. **层 B**：Azure AI Foundry 证据锚定编码与申诉工作台，负责可追溯编码建议和拒付申诉草拟。
5. **层 C**：确定性清算与编排平面，负责 EDI X12 270/271/278/837/835 与 Da Vinci PAS 的 SLA 级提交。
6. 任何未经过认证编码人员签署的自动编码结果都不能进入生产提交链路。
7. 所有影响 DRG 的建议都必须回指到源病历精确证据位置并通过确定性编辑校验。
8. 预授权成功率取决于时效、证据完整性和事务格式合规性。
9. 申诉文书可以由 AI 起草，但必须经过策略闸门后才能对外发送。
10. 多院区推广应按专科线和 payer 组合分批推进，不应一次性全量切换。

## 2. 范围与前提
### 2.1 覆盖能力
- CDI 医生问询与文档特异性缺失补全。
- 住院与门诊编码支持：ICD-10-CM/PCS、CPT/HCPCS、MS-DRG 相关语境。
- 预授权链路支持：HL7 Da Vinci CRD/DTR/PAS 与 EDI X12 278。
- 拒付分析与申诉草拟：基于 X12 835 CARC/RARC 与临床医学必要性证据。
- CMS/OIG 合规留档、审计追溯、发布闸门。
### 2.2 前提假设
- 医疗系统具备企业级 EHR 且支持 SMART on FHIR 应用接入。
- 涉及 PHI 的处理已具备 HIPAA BAA 与 VNet 隔离边界。
- CCS/RHIA 或同等资质编码审核角色可参与最终签署。
- 清算所与 payer 接口通过受控网关契约接入。
### 2.3 强制约束
- 禁止仅凭生成式输出直接完成最终编码提交。
- 禁止输出无法定位到源病历位置的证据引用。
- 禁止将原始 PHI 发往非 BAA 保障的第三方模型端点。
- 禁止绕过 NCCI、MUE/PTP 与 X12 schema 确定性校验。
- 禁止无审批身份和不可篡改日志的生产提交。

## 3. 方案 A：EHR 内嵌 SMART on FHIR 环境 CDI 层
### 3.1 核心价值
- 在医生书写路径中实时捕获编码特异性缺口。
- 将编码提示绑定当前就诊上下文，减少系统切换负担。
- 支撑医生问询闭环并减少后置返工。
- 提升病历源文档完整性，为后续编码和预授权打底。
- 在源头减少“信息不全导致拒付”的可避免风险。
### 3.2 优势画像
- 最适合“点位靠近临床行为”的前置捕获。
- 在交互设计合理时，临床采用率提升更快。
- 对上游文档质量提升作用显著。
### 3.3 局限性
- 单独使用时，不足以覆盖复杂多 payer 的事务编排。
- 若提示策略不当，可能引发临床提示疲劳。
- 覆盖深度受 EHR 模板和专科流程成熟度影响。
---
## 4. 方案 B：Azure AI Foundry 证据锚定编码与申诉工作台
### 4.1 核心价值
- 结合 Document Intelligence 与 AI Search 混合检索实现政策和病历关联。
- 输出编码建议时附带字符级证据跨度回指。
- 可将手术记录、病理、出院小结等多源证据聚合成审核包。
- 对 CARC/RARC 拒付原因生成证据锚定申诉草案。
- 强制 CCS/RHIA 人审签署，防止不合规自动发布。
### 4.2 优势画像
- 在“证据可解释编码”和“可辩护申诉”方面能力最强。
- 便于跨院区形成统一审核模板和质量口径。
- 对审计与法务复核更友好。
### 4.3 局限性
- 依赖 LCD/NCD 与 payer 规则语料持续更新治理。
- 源病历质量与抽取质量会直接影响输出效果。
- 审核队列设计不当会形成新瓶颈。
---
## 5. 方案 C：确定性清算与 Durable 编排层
### 5.1 核心价值
- 提供 X12 270/271/278/837/835 的确定性校验与事务执行。
- 对 Da Vinci PAS 提交、重试、超时处理做 SLA 级编排。
- 支持 Gold-Carding 与 payer 路由策略的明确规则执行。
- 生成不可篡改提交与响应事件链，满足审计要求。
- 将传输可靠性与模型波动解耦。
### 5.2 优势画像
- 在生产事务可靠性、时效性、可追溯性方面最强。
- 对 schema 合规、重放、异常恢复友好。
- 便于运营侧按规则做分级处置。
### 5.3 局限性
- 不擅长语义草拟，需要方案 B 补位。
- 多 payer 异构接口会提高接入复杂度。
- 对重试、队列、死信治理有较高运维要求。

### 9.2 确定性放行伪代码
```python
def release_prior_auth(packet):
    if packet["requiresSigner"] and packet.get("signerRole") not in {"CCS", "RHIA"}:
        return {"ok": False, "reason": "certified_signoff_required"}
    if packet["containsPHI"] and packet.get("trustZone") != "HIPAA_BAA_VNET":
        return {"ok": False, "reason": "phi_boundary_violation"}
    if not packet.get("x12SchemaValid"):

    if not packet.get("ncciEditsPassed"):
        return {"ok": False, "reason": "deterministic_edit_failed"}
    return {"ok": True, "reason": "ready_for_submission"}
```

## 10. 场景 A：多院区住院编码现代化
### 10.1 场景背景
- 区域医疗网络在心内和骨科存在较高编码返工与 DNFB 压力。
- 病历特异性在院区间差异大，导致审核口径不一致。
- 审计团队需要“建议编码 -> 源证据”强关联追溯。
### 10.2 架构决策
- 在高量专科上线层 A 以提升源文档完整性。
- 部署层 B 形成证据锚定编码草案与统一审核工作台。
- 层 C 作为强制事务放行链路，保障对外提交合规。
### 10.3 量化结果
- `measured`：试点 DNFB 天数由 6.4 降至 4.9。
- `measured`：编码首轮通过率提升到 71%。
- `anonymized_reported`：回溯审计准备工时下降 29%。
---
## 11. 场景 B：预授权与拒付申诉提速
### 11.1 场景背景
- 预授权积压和拒付返工拉长了专科项目回款周期。
- 申诉材料质量在院区之间波动明显。
- SLA 违约导致管理成本和 payer 摩擦上升。
### 11.2 架构决策
- 用层 C 承担 278/PAS 的确定性编排、重试、超时治理。
- 用层 B 对 CARC/RARC 做证据锚定申诉草拟。
- 用层 A 提升上游文档完整性，减少可避免缺陷。
### 11.3 量化结果
- `measured`：预授权一次通过率由 82.1% 提升至 90.4%。
- `measured`：重点专科拒付翻案率提升 11.7 个百分点。
- `anonymized_reported`：申诉包中位准备时长下降 34%。

## 12. 量化 FAQ
### Q1：证据锚定编码能降低多少返工？
在实测试点中，单病例编码返工触达次数下降 24% 到 38%。
模板治理更成熟的专科通常位于区间高端。
### Q2：确定性校验链是否能提高 payer 接受率？
是。发布前强制 NCCI/MUE/PTP 与 X12 校验后，可避免拒收率实测下降约 18%。
增益主要来自格式和规则错误的前置消除。
### Q3：clean-claim 提升目标如何设定更现实？
住院+门诊混合组合在前两个季度通常可提升 4 到 9 个百分点。
上游医生问询闭环率越高，提升越稳定。
### Q4：拒付申诉吞吐能提升多少？
证据模板化后，草拟到复核周期实测可缩短 25% 到 40%。
长期效果取决于审核角色配比和队列治理。
### Q5：方案 B 的 ROI 何时成立？
在 `synthetic` 规划中，当拒付回收增量达到 token/算力成本的 1.8 倍以上时，投入性价比明显。
中大型医疗系统配合确定性放行后通常可达到该阈值。
### Q6：严格 PHI 边界会显著拖慢流程吗？
初期合规接入有成本，但稳态实测时延增幅通常低于 6%，同时显著降低隐私风险。

## 17. Good fit / Not for
### Good fit
- 具备集中 RCM 治理与复杂 payer 组合的大型医疗系统。
- 需要编码建议可追溯、事务提交可审计的组织。
- 能执行人审签署与确定性放行的团队。
### Not for
- 希望无认证审核直接自动提交编码的项目。
- 缺乏 HIPAA 边界与治理 owner 的环境。
- 不愿持续维护 payer 规则与确定性编辑规则的组织。

## 18. 推进路径建议
1. 先强化层 C 的确定性事务链，降低外部可避免拒收。
2. 再上线层 B 的证据工作台，提高编码与申诉质量。
3. 最后扩展层 A 的环境 CDI，稳住上游文档完整性。
4. 以专科为单位达标后扩展到院区，再扩展到集团。
5. 建立模型风险和政策变更的周期性治理机制。
---
## 19. 最终建议
采用“三层分工”架构：EHR 环境捕获提升源文档质量，Foundry 证据工作台提升编码与申诉质量，确定性事务编排保障合规提交可靠性。
该设计能在监管医疗环境中平衡效率、合规与财务回报，并保持明确的人类责任边界。
长期效果取决于治理纪律、证据完整性以及对高影响动作的确定性放行控制。
